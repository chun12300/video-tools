# 🎬 影片小工具箱

純前端的影片處理網頁工具箱,所有轉換都透過 [ffmpeg.wasm](https://ffmpegwasm.netlify.app/)
**在你的瀏覽器裡完成**,影片檔案不會上傳到任何伺服器。

包含三個工具:

- 🎞️ **影片合併剪輯**(`merge.html`)— 選多支影片、各剪一段、照順序合併輸出成一支 MP4;可自動剪掉無聲片段
- 🖼️ **影片轉 GIF**(`gif.html`)— 剪一段影片,選擇尺寸與幀率轉成 GIF
- 📝 **語音辨識字幕**(`subtitle.html`)— AI 辨識語音生成繁中字幕,逐句校正後匯出 SRT 或燒進影片

💻 建議使用電腦操作(手機瀏覽器可用,但轉檔速度與記憶體限制更明顯);語音辨識字幕僅建議在電腦使用。

## 功能

### 影片合併剪輯

- 📂 一次選擇或拖放多個影片檔(MP4、MOV、WebM)
- 📋 影片清單:拖曳(或 ↑↓ 按鈕)調整順序、移除單支影片
- ✂️ 每支影片可個別設定要保留的起訖時間(滑桿+數字+一鍵取目前播放位置)
- 🎬 依清單順序合併成一支 MP4(H.264 + AAC)下載;沒有聲音的影片會自動墊上靜音軌,避免聲音錯位
- 📊 顯示總檔案大小,超過建議上限(500 MB)即警告;影片逐支處理以控制記憶體
- 🔇 **自動剪輯(剪掉無聲片段)**:開啟後以 Web Audio API 分析音軌,
  自動偵測無聲/停頓片段;靈敏度三段(保守 1.5 秒/標準 0.8 秒/積極 0.4 秒),
  剪除段前後保留 0.15 秒緩衝。偵測結果會先列出清單讓你逐段確認(可勾「保留」),
  並顯示「原始總長 → 剪輯後長度、省下幾秒」,按「確認並合併」才真正執行;
  沒有音軌或幾乎全程無聲的影片會提示並整支保留

### 影片轉 GIF

- ✂️ 剪出片段、選擇尺寸(240/360/480px)與幀率(8–24 fps)
- 💡 片段過長或產出檔案過大時給予友善提示
- 🖼️ 以調色盤兩階段濾鏡產生高品質 GIF

### 語音辨識字幕

- 🎙️ Whisper(small,q8 量化,約 250 MB,首次使用下載一次後由瀏覽器快取)在瀏覽器內辨識,
  預設繁體中文;模型輸出的簡體字以 OpenCC 自動轉成台灣正體(含用語轉換)
- ✏️ 字幕編輯模式:逐句列出時間軸與文字、直接修改、調整起訖秒數、
  合併/拆分/新增/刪除;點 ▶ 跳到該句邊聽邊校正;編輯自動暫存 localStorage
- ⬇️ 匯出 SRT(UTF-8 + BOM,可上傳 YouTube 等平台)
- 🔥 字幕燒進影片:ffmpeg.wasm 的 libass `subtitles` 濾鏡 + Noto Sans TC 字型
  (SIL OFL 授權,約 7 MB,燒錄時才下載)
- 🔁 「影片合併剪輯」的結果可一鍵帶進字幕工具(IndexedDB 交接,不落地)

## 使用方式

1. **選影片** — 進入工具後,把影片拖進頁面或點擊選擇
2. **設定** — 剪出片段、調整順序或輸出選項
3. **下載** — 按下轉換/合併,完成後預覽並下載

## 部署到 GitHub Pages

這是純靜態網站,不需要任何建置步驟。到儲存庫的 **Settings → Pages**,
**Source** 選「Deploy from a branch」、Branch 選 `main` + `/ (root)`(僅需設定一次)。
之後每次推送到 `main` 都會自動重新部署,網站在
`https://<帳號>.github.io/<儲存庫名>/`,部署進度可在 **Actions** 頁籤查看。

## 本機開發

因為瀏覽器對 `file://` 的限制,請用任何靜態伺服器開啟,例如:

```bash
python3 -m http.server 8000
# 然後打開 http://localhost:8000
```

## 技術說明

- 純 HTML / CSS / JavaScript,無框架、無建置步驟
- ffmpeg.wasm(`@ffmpeg/ffmpeg` 0.12 + 單執行緒版 `@ffmpeg/core`)從 CDN 載入(jsDelivr,失敗時自動改用 unpkg);共用載入邏輯在 `ffmpeg-loader.js`
- GitHub Pages 無法設定 COOP/COEP 標頭,因此刻意採用**單執行緒**核心(不需要 `SharedArrayBuffer`)
- CDN 與網站不同源,Worker 無法直接以跨網域 URL 建立,因此 worker、core、wasm 都先用 `toBlobURL` 轉成同源 blob URL 再載入
- 合併流程:逐支影片「剪輯 + 正規化」(統一為相同解析度、30fps、H.264/yuv420p + AAC 44.1kHz 立體聲,不足補黑邊、無聲補靜音),再用 concat demuxer 以串流複製(`-c copy`)串接,避免二次編碼
- 自動剪輯:以 Web Audio API(`decodeAudioData` 重取樣到 8kHz)計算每 50ms 的 RMS 音量,
  門檻取「第 95 百分位音量 − 25 dB」並夾在 −55 ~ −35 dBFS 之間(自適應不同錄音音量);
  低於門檻且連續達靈敏度秒數的區段即為剪除候選。剪除區間直接展開成多個「保留區間」
  進入既有的正規化流程,每一格畫面仍然只編碼一次
- GIF 以 `palettegen` / `paletteuse` 兩階段調色盤濾鏡產生

## 已知限制

- **首次轉換需下載約 25 MB** 的 ffmpeg 核心(之後由瀏覽器快取)
- **單執行緒轉換速度較慢**:合併會逐支重新編碼(統一規格才能無縫串接),大約比影片實際長度慢數倍,長片請耐心等候
- **記憶體限制**:wasm 定址空間至多 2 GB 且與分頁共用記憶體;單支影片上限設 500 MB,總量超過 500 MB 會警告。過大時可能轉檔失敗或分頁當掉,建議剪短、減量或分批合併
- **編碼支援**:HEVC/H.265 等部分編碼的 MOV 檔可能無法解碼,建議使用 H.264 MP4 或 WebM;
  iPhone 使用者可到「設定 → 相機 → 格式」改選「最相容」避免拍出 HEVC
- **自動剪輯以音量為依據**:只看「夠不夠大聲」,無法分辨語意;背景音樂、風聲、雜訊大的影片
  偵測不到停頓,氣音或極小聲說話則可能被誤判為無聲——請務必在確認清單裡檢查後再合併
- **重新編碼有畫質損失**:合併輸出以 CRF 23 重新編碼,並統一到同一個解析度(以面積最大的一支為準、寬度上限 1280),不同長寬比的影片會補黑邊
- **GIF 本身的限制**:最多 256 色、檔案效率差;長片段請剪短或降低尺寸/幀率
- **語音辨識**:Whisper small 對清晰的中文口語有不錯的準確度,但專有名詞、
  同音字、多人交談、背景音樂大的內容仍會辨錯,務必在編輯模式校正;
  辨識在單執行緒 wasm 上執行,速度可能比影片長度更久;
  無聲片段會被跳過以減少幻覺字幕,但仍可能出現「謝謝觀看」之類的幻覺句
- 需要較新的瀏覽器(支援 WebAssembly 與 module worker);建議使用桌面版 Chrome / Edge / Firefox
